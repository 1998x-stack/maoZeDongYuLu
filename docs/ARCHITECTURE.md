# 文献阅读与卡片系统：设计与校验方案

## 1. 目标与非目标

本项目是**历史文献阅读与资料整理工具**，以便于核对的引文、原始出处和章节位置为核心。目标是提升章节导航、长篇阅读、检索精度、原文复制与静态图片导出；不对历史人物或文本观点进行评价，不将未核实的出处、日期和解释包装成确定事实。

此次改造维持纯静态网页，没有新增运行时依赖、后端、账户、第三方文字/图片上传服务，也没有重写 `jsons/` 原始文本。图片模板为原创的中性阅读版式，而不是政治宣传模板。

## 2. 对原始版本的代码审查

| 位置 | 原问题 | 本轮处理 |
|---|---|---|
| `index.html` 数据加载 | 35 个 JSON 文件串行加载，失败后可能继续展示不完整数据 | 使用显式文件清单并发读取，任一文件加载/解析失败时停止生成统计及检索结果 |
| `renderQuotations` | `content.split('\n——')` 仅使用第一组正文、第一组出处，其余文本会在显示中丢失 | 单行出处状态机逐段拆分，保留没有来源标注的余段 |
| 搜索 | 以 `contentList` 数组元素作为搜索命中单位，一次可能返回整个大章节 | 以解析后的记录作为命中单位，检索正文、出处、章节和分类 |
| DOM 渲染 | 直接拼接字符串到 `innerHTML`，可能把数据当作可执行 HTML | 使用 DOM 节点和 `textContent`，高亮用安全的 `mark` 元素创建 |
| 章节与前言 | 附属资料和正文混用时可能出现作者归属误导 | 目录、另有署名的再版前言独立阅读，不计入正文统计及图片生成 |
| 文案与统计 | 原始 JSON 数组长度不能准确表示语录数 | 明确显示“整理记录数”，从实际拆分的记录计算 |
| 图片分享 | 仅有网页卡片，没有可下载的独立图片 | 同一个 Canvas 布局负责实时预览、分页与本地 PNG 导出 |
| 部署 | 上传整个仓库、只验证 JSON 是否可解析 | 对每份文件建立清单/结构校验和回归测试，仅部署运行需要的目录 |

## 3. 数据契约与引用边界

原始单元是 `chapter.id`、`chapter.chapter`、`chapter.classify` 和 `chapter.contentList[]`。某个 `contentList` 字符串可能包含多条正文与各自的 `——` 出处行。`splitBlock` 只识别**独立行以 `——` 开始**的出处，不从正文中猜测出处；按原有顺序得到 `{ text, source }`。尾部未配对文字仍保留，但 `source` 为空。使用 `{chapter.id}:{blockIndex}:{recordIndex}` 作为当前数据快照内的稳定记录定位，正文与出处字段原样供阅读和搜索使用。

此规则不是版本学意义上的自动校勘。来源中若存在不规则换行、引文内部包含作为正文的破折号起首行、或多个作者/作品的复杂排版，需要人工标注后再更新整理数据。`chapter_01` 是目录、`chapter_02` 是另有署名的再版前言，不能在数据层面标为正文引文。

## 4. 页面信息架构

- **左侧目录**：全局检索、资料目录、正文篇章和按实际记录计算的数字；窄屏改为页面上部可滚动目录。
- **阅读区域**：章节/搜索状态标题、清除筛选按钮、逐条正文、完整仓库来源、复制正文、记录链接和图片入口。
- **卡片工作台**：原生 `dialog`、主题单选、画幅比例、字号、Canvas 实时预览、逐页切换、逐页 PNG 下载和完整来源说明。
- **中性视觉**：纸白与低饱和蓝灰、中文衬线正文、对比度明确的控制按钮、可见键盘焦点，避免夸张装饰影响长文本阅读。

## 5. 图片处理流程及限制

`layoutCard` 先用 Canvas 字宽测量逐字折行，再根据画幅计算每页最大行数；`drawCard` 使用相同布局渲染预览和导出。这使长文能够跨页保存而非被 CSS 溢出裁切。每页保留章节、记录号和页码；独立来源过长时图片会明确标注“阅读页查看完整出处”，工作台的“完整出处”仍显示未经缩写的原始字段。

目前导出的是**单张 PNG**，长文需要逐页下载；尚无 ZIP、自动生成概括性标题、智能文案重写、图片背景资产、外部图片 API 或原创文献证明。首版只做原样摘录，避免模型生成的概括混入原始文献。

## 6. 测试矩阵与上线门槛

1. 清单必须与 `jsons/*.json` 完全一致，所有文件均能解析、符合章节结构、编号不重复；正文记录数为从文本实际计算的结果。
2. 解析必须覆盖多个出处连续出现、CRLF、无出处尾段、空内容、附属资料排除。
3. 全文与章节筛选组合、来源字段命中和稳定记录 ID 通过回归测试。
4. Canvas 测试覆盖中文/Unicode、空行、三种画幅、字号上下限、分页拼接完整性、页脚与正文的安全间距、原始出处或明确的来源提示。
5. 进入 `main` 前 CI 完成上述测试与 JavaScript 语法检查；GitHub Pages 在校验通过后仅发布静态运行资产。

仍需真实浏览器检验：Safari/iOS 下载行为、不同系统中文字体对换行的影响、屏幕阅读器下 `dialog` 的焦点流、触屏目录与长文分页，以及网络失败时的错误提示。单元测试不能代替这些端到端检查。

## 7. 后续迭代（需另行验收）

**阶段 A：人工来源校勘。** 为每条记录增加明确的作品名、文献版次、页码、署名、日期字段与验证状态。保留来源文本与规范化元数据的区别，对无法确认的信息展示“未核实”，不从章节标题推断。

**阶段 B：文献结构可视化。** 在可验证来源数据上增加章节分布、版本差异和来源类型统计。时间轴只有在逐条日期可靠且缺失比例明确时才开放；可视化展示本仓库样本而非全部历史言论。

**阶段 C：导出完善。** 完成跨浏览器导出体验检查之后，可增加带完整出处页的多卡打包、导出前文本/来源逐页核对、分享时的记录链接和清晰的版权提示。
