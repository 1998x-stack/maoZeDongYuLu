# 文献阅读与卡片系统 · 架构与质量边界

## 1. 产品定位与可验证范围

本仓库提供对现有 JSON 整理文本的**阅读、查找、定位和本地图片导出**，不是经过独立逐句校勘的权威文献数据库。程序只能判断文字是否出现在仓库中以及是否匹配当前格式规则；不能仅凭日期、标题和页码的文本外观确认原始出版物的真实性、完整性或归属。所有数据统计都附有“本仓库整理记录”的口径。

前端保持无需后端、账号或新增 npm 运行依赖的静态架构。原始整理文件 `jsons/` 不在读取过程中被修改；未来人工校勘记录应作为独立、可审查的层加入。

## 2. 模块职责与数据流

```text
jsons/（35 份编号章节 JSON + 独立 metadata.json）
     ↓ 并发读取，任一失败即停止构建不完整索引
src/corpus.mjs（字段校验 → 保守分段 → 原始文件位置 → 记录索引）
     ↓
src/app.mjs（全文／章节／出处状态筛选 → 章节导航、逐条阅读、复制与来源链接）
     ↓
src/card.mjs（Canvas 同一布局完成实时预览、自动分页和逐页 PNG 下载）

scripts/audit-content.mjs + tests/*.test.mjs
     ↓ 内容覆盖、疑似格式问题与回归检查
GitHub Actions CI → main 部署校验 → 仅发布静态运行文件
```

`src/corpus.mjs` 不依赖浏览器 UI，可在 Node 中使用真实仓库数据测试。`src/app.mjs` 使用 DOM 文本节点渲染原文和检索命中，避免把资料文本通过 `innerHTML` 注入页面。`content.css` 用于来源、原始位置及编辑说明的视觉层级，`styles.css` 仍保存基础版式。

## 3. 为什么必须保留原始数据位置

`contentList` 的一个字符串并不等于一条引文：某些块包含多段正文及各自的出处、某些含单独的来源说明；目录和再版前言不应混入正文引文。浏览记录使用 `chapterId:blockIndex:recordIndex` 作为**当前快照内**的定位，额外提供章内顺序号、原始 JSON 文件及 `contentList[blockIndex - 1]` 以便交叉检查。

改变自动分段规则时，`recordIndex` 可能变化。因此，正式建立跨版本外部引用前，应引入数据版本号、原始块及正文校验和、旧 ID 映射等手段；当前 ID 仅用于仓库内的导航和原始资料定位。

## 4. 解析规则与人工校勘的分界

当前 `splitBlock` 按行识别三类资料所附来源：① 独立行首 `——`；② 有日期／页码／版次线索的 `《作品》` 书目行；③ 形如“在……讲话／谈话＋括号日期＋出版线索”的独立说明行。个别独立来源说明按精确格式识别，并标记 `sourceIsNote`，不将其冒充出版物书目。有明显书名号不成对的来源文字原样保留，标记 `sourceNeedsReview`。

这一规则只做**保守的格式识别**：不会自动补全版次、将来源文本中的日期当作已核实发布日期，也不会利用生成式模型改写正文。模糊的折行、正文中形似来源的文字及多作者复杂结构，应以单独的人工校勘层处理，而不是无限扩大正则规则。

目录和另有署名的再版前言按附属资料单列。`analysisList` 中的模板化描述不用于正文、图片或事实判断。完整异常分类、具体章节样例和人工审核步骤见 [内容审计与编辑工作流](CONTENT_AUDIT.md)。

## 5. UI 信息架构与阅读设计

阅读页面分成四个清楚区块：章节／搜索／出处状态控制；全语料概况；数据使用与引用限制说明；逐条正文与仓库来源。每条记录都提供章内位置、原文、来源文字或缺失说明、原始 JSON 跳转，以及复制正文、复制正文和来源、记录链接、生成图片四种操作。

来源文本出现在醒目的独立栏位，页面用“原整理资料所附”“尚未独立核验”等标注避免把原始数据字段解释为已确认史实。页面不以政治立场、意见倾向或主观评价给引文评分、排序或撰写推广说明。

图片工作台保持三个低干扰模板、三种画幅和字号调节。原文与来源分区；长引文逐页导出、保留记录号和页码。来源太长时卡片明确提示回到阅读页，而非截掉出处后假称完整。图片生成在客户端进行，无文本上传。

## 6. 质量门槛与测试

- **结构完整性**：编号章节清单与真实文件匹配，目录、前言不计为引文；章节字段校验及重复 ID 错误明确报告。
- **解析保真**：真实第 08、14、19、32、35 章及合成样例覆盖三类来源与校训说明；各原始块在拆分后不丢失非空白字符；标点和不规则书名号保留供核对。
- **检索一致性**：正文、来源、章节与出处状态组合筛选，清除过滤及原始 JSON 定位使用同一条记录；禁止把占位 `analysisList` 展示为独立解释。
- **图片**：原文 Unicode 换行、不同画幅和字号分页、页脚不重叠、来源信息可查；自动化测试不能代替 Safari／iOS 或其他真实浏览器的下载验收。
- **内容审计**：CI 运行 `node scripts/audit-content.mjs`，输出各章数量、缺失来源、单独来源说明、不规范引用标记及模板分析条目。计数为诊断结果，不作独立真实性保证。
- **部署**：通过 CI 后，Pages 工作流只复制 `index.html`、`styles.css`、`content.css`、`src/` 和 `jsons/`，避免发布非站点所需资料或漏掉新增样式。

## 7. 下一阶段：先证据，后内容

**A. 来源校勘与版本记录**：为每条记录保存出版物、版本、页码、原资料截图／页面位置、校勘人员和审核状态，保留整理文本与修订差异；未知字段保持空白而不是自动猜测。

**B. 有依据的历史背景资料**：确有可验证来源时，新增与正文明确分开的编者说明、作品上下文和不同版次对照，每段解释都注明来源及编辑状态；不直接复用 `analysisList` 占位文本。

**C. 来源结构可视化**：仅展示当前仓库的分类／来源状态及已核实字段的覆盖范围。时间轴必须先满足日期证据和缺失说明，不能把从不同文献里出现的日期直接当作同一统计口径的时间序列。

**D. 体验验收与导出**：真实浏览器自动化、移动端和读屏操作、原始数据链接、长文打印以及多页图片批量导出。在完成前，不宣称已全面通过端到端验收。
