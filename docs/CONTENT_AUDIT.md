# 语料内容审计与编辑工作流

## 1. 本轮问题定位

此前阅读器只将独立行首的 `——` 识别为出处，但仓库各章使用多种排版方式。典型资料位置（下标从 0 开始，以下仅描述格式，不代替原文核对）：

| 原始文件 | 观察到的格式问题 | 本版处理 |
|---|---|---|
| `jsons/03_一、共产党.json` | 同一 `contentList` 字符串内有多段正文、多个 `——` 书目行 | 按来源行切分，并保留同一原始块内的次序 |
| `jsons/19_十七、为人民服务.json`、`35_三十三、学习.json` | 正文后独立行直接以 `《作品》` 开始，未使用 `——` | 仅在后文出现日期、版次、页码等书目特征时识别为资料所附出处 |
| `jsons/08_六、帝国主义和一切反动派都是纸老虎.json` | 单一原始块内反复交替出现正文和“在……讲话／谈话＋日期＋刊物”来源行 | 识别活动名称、括号日期及后续刊物／出版线索的组合，逐段分开；不从内容推测来源 |
| `jsons/14_十二、政治工作.json` | 同一块内含单独的校训来源说明及另一段正文的活动日期来源；另有书名号格式异常 | 校训说明按独立来源说明分隔；保留不规范书目文字，标记为人工复核对象，不静默改写 |
| `jsons/32_三十、青年.json` | 单个数组元素内包含两组不同来源格式的正文／出处 | 拆为可分别定位的阅读记录 |
| `jsons/04_二、阶级和阶级斗争.json` | 存在未使用书名号的活动来源及不成对的书名号 | 优先保留原始字符串，识别其来源行并将不规范标注列入审计 |

`analysisList` 中有大量重复的“核心观点阐述＋字数”模板文本。这些是整理数据字段而不是经过文献校勘的独立说明；网站不会把它们呈现为专家分析、原话背景或事实断言。

## 2. 当前审计口径

运行 `node scripts/audit-content.mjs` 得到的是**解析程序在当前 JSON 快照下的输出**，不是经过独立核对的史料数量、真实来源覆盖率或权威版次条数。来源状态只描述“原整理文件有无被识别到的来源或说明行”。本轮测试同时检查中文和 Unicode 换行、原始文本非空白字符保存、目录／前言隔离，以及真实章节中交替出现的多种来源格式。

即便所有记录都被识别出来源行，仍可能存在标点、 OCR／录入错误、缺句、省略、跨行出处、来源文字自身错误、多个版次混用、作者署名歧义及日期对应关系错误。审计中的“疑似残留书目行 = 0”只表示被**现有规则**匹配的项目为 0，不能证明没有其他异常。篇章之间的总量、标签或来源分布也不能直接推断历史发表频率。

## 3. 数据模型与可复核位置

阅读记录字段包括 `id`、`text`、`source`、`chapterId`、`chapter`、`classify`、`ordinal`、`sourceFile`、`blockIndex`、`recordIndex`、`sourceIsNote` 和 `sourceNeedsReview`。`blockIndex`／`recordIndex` 用于从页面直接返回 `jsons/<文件名>` 的 `contentList[blockIndex-1]`。`source` 仅保留仓库内文字，不等价于已经人工查到原始出版物。

`id = chapterId:blockIndex:recordIndex` 只保证**当前原始数据与解析规则**下的位置。将来如果需要跨版本永久定位，应额外保存版本号、原始块校验和、规范化全文校验和以及旧 ID → 新 ID 的映射，而非把现在的 ID 当作永不变化的历史文献标识符。

## 4. 推荐的人工校勘字段

不要将自动正则提取的出版信息直接标记为已核实。未来建议使用**独立于原始 JSON**的人工核对文件，例如：

```json
{
  "recordId": "chapter_XX:N:M",
  "datasetRevision": "git-commit-sha",
  "editorialStatus": "unreviewed",
  "displayText": null,
  "workTitle": null,
  "edition": null,
  "publisher": null,
  "pageRange": null,
  "dateAsPrinted": null,
  "sourceLocator": null,
  "checkedAgainst": null,
  "checkedBy": null,
  "checkedAt": null,
  "notes": null
}
```

`null` 明确表示未知；`editorialStatus` 推荐分成 `unreviewed`、`needs_correction`、`verified_against_named_edition` 等互不混淆的状态。只有核对具体的可访问出版物和页码后，才允许填充 `checkedAgainst`、可验证链接和已核实状态。需要更正文字时，既保存原整理值，也保存核对后的显示值与差异，不覆盖历史快照。

## 5. 实际编辑与审核流程

1. **选择待审记录**：优先处理 `sourceNeedsReview`、`sourceIsNote`、混合出处和复杂长文本记录。以原始文件及 `contentList` 下标定位，避免复制页面卡片后二次损失上下文。
2. **核对段落边界**：确认正文、出处或编者说明的真实分界。若出处折行、正文中带有类似书目的行，应以显式人工覆盖规则替代继续扩大自动识别正则。
3. **核对版本和字段**：对照实际出版物的书名、版次、日期、页码、原始标点与省略情况；记录核对依据。没有依据时保留未知，不因看似合理就填入。
4. **双人审查关键修订**：任何改变引文文字、归属、出处或原始段落数的修订，分别保存原文、修订文本、理由和审核记录；不得只写“AI 已确认”。
5. **同步检索与卡片**：新增字段或校正结果应同时驱动阅读器、复制、全文搜索和 PNG 图片，避免图片正文与文献详情不一致。
6. **回归与发布**：运行 `node --test tests/*.test.mjs` 及 `node scripts/audit-content.mjs`；人工复核更改涉及的真实记录，再检查手机和桌面浏览器中的定位链接、复制与图片排版。CI 通过不等于人工校勘完成。

## 6. 当前尚未完成的工作

本次升级**没有**访问外部历史出版物逐句核对，没有批量编写观点解释，没有给缺失元数据编造日期，也没有进行真实手机浏览器端到端截图或下载验收。下一阶段应把人工校勘列表与校订状态接入页面，只有存在可查证的资料时再增加作者署名、日期、版次对照及来源可视化。
